# ie-jobs-collector
Public-job-board collector for Ireland-based roles. Hourly GitHub Actions run pulls public ATS feeds (Greenhouse, Lever, Ashby, Workday, SmartRecruiters, Workable, Recruitee, Gem, Rippling) and commits the raw public listings under docs-data/. Public job data only - no personal data, no credentials.

Description handling: full provider text is retained, with no 4,000-character truncation. Detail-only descriptions have a 24-hour successful-cache TTL; title, URL or provider-updated changes invalidate the cache. Failed refreshes retain old text explicitly marked STALE_CACHE. Failed requests wait six hours, and 404s wait 24 hours before another attempt. Legacy caches without freshness metadata are refreshed gradually. Each run allows at most 100 detail requests and six minutes of detail-refresh start time, so a migration cannot create an unbounded request burst. Deferred descriptions remain explicitly missing or stale; these are not eligibility clearances.

Regression tests: `python -m unittest discover -s tests -v` and `python -m unittest test_descriptions -v`.

Freshness contract (source_receipt_schema_version 3): every health.json carries a per-run `run_id`, `checked_at`, `expected_interval_seconds` and `fresh_until` (checked_at plus 1.5 intervals). A reader must treat a response past `fresh_until`, or one whose `run_id` repeats across polls, as a cached copy, not current data. Fetch with a cache-busting query parameter and re-check `run_id`.

Queue semantics: raw-irish-queue.json holds active Irish-location matches (`eligibility_review_state: IRELAND_LOCATION_MATCHED`) plus broad-region remote roles (`REMOTE_COUNTRY_REVIEW_PENDING`). Remote-country eligibility is a review state, never an exclusion; a pending remote role stays queued until review resolves it. Each row is ranked (`queue_rank`): review-verified fits first, then lane-matched candidates, then remote-review rows, then raw. Inside a tier, roles with an explicit stated closing date come first (ascending), then the most recently new or changed. `application_deadline` is set only from an explicit closing/apply-by cue in the provider text, with the evidence snippet kept in `application_deadline_snippet`. Counts are split in `fit_counts` (raw, remote-pending, verified fit/unfit, not reviewed) and `review_backlog` (unreviewed count, oldest first-seen and its age in days). Review decisions (`review_state`, `reviewed_at`, `review_note`) persist across runs; a materially changed description invalidates the earlier verdict.

Pagination receipts: every source receipt carries `pagination_state` and, for single-response full-list providers (Ashby, Lever, Gem, Rippling, Workable), a `pagination_proof` with the verification method, envelope, row and distinct-ID counts and the provider API reference. Greenhouse, SmartRecruiters and Workday keep their existing total/continuation proofs. Continuation metadata, duplicated IDs or missing IDs fail closed to INCOMPLETE; an unexpected envelope stays NOT_VERIFIED.

Workday malformed-record quarantine: records with a stable ID but missing title or owning path are quarantined with ID and reason. Valid records remain ingestible, while the source is explicitly DEGRADED_PARTIAL. A partial source never advances its last fully successful timestamp or marks unseen prior jobs removed. Missing stable identity or unknown schema errors still fail closed. Quarantine evidence is in source health and durable source state; it does not qualify vacancies or enable delivery.
